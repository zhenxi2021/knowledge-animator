# Scene Patterns · 八种知识图示套路

> 大多数技术原理都能套进下面 8 种图之一。先识别套路，再动笔。

## 1. 链路流水线（Pipeline）
**适用**：消息从 A 到 B 走过的所有环节。
**例**：RPC 调用链、TCP 包的一生、HTTPS 握手、Linux 进程 fork。

**画法**：
- 横向一排"模块"（应用 / 框架 / socket / 内核 / 网卡 / 物理层）
- 节点之间画一条**单向**主路径（p1, p2, p3...），packet 沿其飞行
- 重要节点高亮 + 标签
- 配 `lab` 让读者改变其中一环的参数（包大小、超时、加密开关）

**典型步骤**：
1. enter 各模块
2. packet 沿 p1 进入第 1 个环节
3. focus 环节 1 + tag 说明该层在做什么
4. packet 沿 p2 进入下一环节
5. ...

## 2. 状态机（FSM）
**适用**：有限个状态、有限条迁移边。
**例**：TCP 慢启动/拥塞避免/快恢复、HTTPS 状态、HTTP 2 流、数据库事务。

**画法**：
- 状态用大方框，2-3 列或成三角
- 迁移边用曲线（弯出在状态外侧，避免重叠）
- **强信号 vs 弱信号用颜色区分**（如红=超时，黄=3 dup-ACK）
- 重要 transition 加 `tag` 解释触发条件

**典型步骤**：
1. enter 起始状态
2. packet 沿某条边 + focus 目标状态
3. tag 在边上："cwnd ≥ ssthresh"
4. ...

## 3. 分层协议（Layered Protocol）
**适用**：OSI、TCP/IP、5G 协议栈、HTTP→TLS→TCP→IP。
**画法**：
- 垂直 4-7 层带，水平方向每层独立
- 左侧标注「应用 / 传输 / 网络 / 链路」
- 同一列的同高度节点代表一个数据包在每一层的形态
- **packet 从左上走到右下**，每过一层变一次形状（可加 `label` 改写）

## 4. 反馈环 / 控制回路（Feedback Loop）
**适用**：PID、AIMD、拥塞控制、恒温器。
**画法**：
- 中央一个"被控对象"
- 周围形成回路：测量 → 比较 → 决策 → 执行 → 回到测量
- **动画的核心是"绕一圈"**：packet 沿整条回路走一圈，配 `tag` 标注每步

**例（PID）**：设定值 → 求差 → PID 控制器 → 物理过程 → 测量值 → 回到求差

## 5. 并发时序（Sequence / Race）
**适用**：线程交互、锁、Raft 选举、分布式事务。
**画法**：
- 每条线 = 一个 actor
- 横向是时间
- 消息/事件是水平箭头（用 packet 飞行）
- 关键事件加 `tag`（如「过半响应」）

## 6. 数据结构（Structure）
**适用**：B 树、红黑树、跳表、LSM、Zigzag 编码。
**画法**：
- 节点用圆圈（不是方框）
- 指针用细线 + 箭头
- 操作分步骤：插入 / 删除 / 查找各一组
- **配色强调"被访问的路径"**：`focus` 走过的节点

## 7. 对比权衡（Trade-off）
**适用**：CAP、SQL vs NoSQL、TCP vs UDP、Reno vs CUBIC。
**画法**：
- 用 `compare` 页（表格）+ 关键参数图（散点 / 坐标）
- 每行高亮 = 一步
- 一句话核心权衡写 `note`：例如「CUBIC 用 RTT 无关的三次函数解决 Reno 的 RTT 不公平」

## 8. 端到端串讲（End-to-end）
**适用**：把前面所有 scene 的关键画面串成一条线。
**画法**：
- 复用前面 scene 的核心节点，放在一条统一时间轴上
- 大段时间轴在底部（x = 时间 / RTT / 事件数）
- 关键事件用 `tag` 标
- **这一步是"补漏"的**：让读者拿到一张带时间感的全景

## 套路选择决策树

```
你的知识核心是什么？
├── "一个东西从 A 到 B 怎么走"          → 1. 链路流水线
├── "有几个状态、状态之间怎么变"        → 2. 状态机
├── "在每个抽象层上是什么形态"          → 3. 分层协议
├── "如何根据反馈调整自己"              → 4. 反馈环
├── "几个参与者/线程的交互"            → 5. 并发时序
├── "内部怎么组织 / 怎么查 / 怎么改"    → 6. 数据结构
├── "两种做法的核心差异"                → 7. 对比权衡
└── "整个过程从头到尾走一遍"           → 8. 端到端串讲
```

## 套路可以混用

一个好的课件常常是套路的组合：
- 状态机（套路 2） + 反馈环（套路 4） = 拥塞控制
- 链路流水线（套路 1） + 分层协议（套路 3） = HTTP/3 over QUIC
- 数据结构（套路 6） + 并发时序（套路 5） = ConcurrentHashMap

不要拘泥——动画服务的目的是"让读者把心智模型建对"，套路只是手段。
